# Conference Tracker: установка и использование

Подробная инструкция к плагину-виджету для Obsidian: как установить, открыть панель,
добавлять события, встраивать виджет в заметки, где хранятся данные и что делать,
если что-то не работает.

## 1. Что делает плагин

Плагин добавляет в Obsidian виджет «Конференции» — он показывает:

- **ближайшее событие** и число дней до него (или «идёт сейчас»);
- **список событий** с фильтрами «Предстоящие / Все / Прошедшие»;
- **карточки** с датами и местом ближайшего проведения, заметкой и ссылкой на сайт;
- **строку «Прошлый раз»** — дату и место актуального прошлого проведения;
- **статусы**: «Через 2 дня», «Завтра», «Сегодня», «Идёт · день 2 из 3»,
  «Последний день», «Завершилось 5 дней назад», «Дата уточняется»;
- **события без точной даты** — с ориентировочным месяцем, пока организаторы не
  объявили даты;
- **динамические даты и места** — плагин не хранит их в коде, а загружает
  с официальных сайтов при запуске и при открытии панели.

Виджет доступен в двух местах:

1. **Правая боковая панель** — постоянный дашборд.
2. **Блок `conferences` в любой заметке** — например, в заметке-дневнике или
   в MOC (Map of Content) по мероприятиям.

В коде плагина нет дат и мест — только названия, ссылки и источники. При запуске
и при открытии панели плагин читает официальные страницы и заполняет **проведения**:
у каждого свои даты, место, ссылка и пометка, откуда оно взялось — вручную или с сайта.
Пока данные не загрузились, карточка честно показывает «Дата уточняется» и
«Место уточняется».

Показывается только актуальное прошлое: проведение **текущего года**, если событие
уже прошло, или **прошлого года**, если оно ещё ожидается в текущем. Более старые
годы в интерфейс не попадают.

У «Дня поля» дополнительно задан список разрешённых регионов — **Новосибирская область
и Алтайский край**. Проведения в других регионах не показываются и не добавляются
автообновлением.

Загрузка дат включена по умолчанию и работает только на чтение страниц:
плагин запрашивает адреса из поля «Сайт» и блок «Источники», ищет даты и место
и добавляет проведение. Ничего не отправляется наружу, кроме этих запросов;
в настройках загрузку можно выключить — тогда плагин работает офлайн, а даты
вносятся вручную. Ручные будущие даты автообновление не перезаписывает.

## 2. Требования

- Obsidian **1.4.0 или новее** (десктоп или мобильный).
- Включённые сторонние плагины (выключенный «Ограниченный режим» / Restricted mode).
- Сборка не нужна: плагин — это три файла, которые Obsidian загружает напрямую.

## 3. Установка

Плагина нет в каталоге Community plugins, поэтому он ставится вручную — копированием
папки. Это один раз и без терминала.

### 3.1. Подготовка

1. Скачайте репозиторий: на странице GitHub нажмите **Code → Download ZIP** и
   распакуйте архив (или `git clone`).
2. Внутри архива найдите папку **`conference-tracker`**. В ней должны лежать
   `manifest.json`, `main.js` и `styles.css`.

### 3.2. Windows

1. Откройте папку вашего хранилища (vault). Обычно это
   `C:\Users\<имя>\Documents\<Название хранилища>`.
2. Включите показ скрытых файлов: **Проводник → Вид → Показать → Скрытые элементы**.
3. Перейдите в `.obsidian\plugins`. Если папки `plugins` нет — создайте её.
4. Скопируйте туда папку `conference-tracker` целиком.

Итог: `...\<хранилище>\.obsidian\plugins\conference-tracker\manifest.json`.

### 3.3. macOS

1. В Finder откройте папку хранилища (часто `~/Documents/<Название хранилища>`).
2. Нажмите **Cmd + Shift + .** (точка), чтобы увидеть скрытые папки.
3. Перейдите в `.obsidian/plugins` (создайте `plugins`, если её нет).
4. Скопируйте папку `conference-tracker`.

### 3.4. Linux

```bash
cp -r conference-tracker "<путь к хранилищу>/.obsidian/plugins/"
```

Скрытые файлы в файловом менеджере включаются сочетанием **Ctrl + H**.

### 3.5. Мобильные устройства

Плагин работает и на iOS/iPadOS, и на Android, но папку нужно скопировать в хранилище
через файловый менеджер:

- **iOS/iPadOS:** приложение «Файлы» → «На iPhone» → `Obsidian` → `<хранилище>` →
  `.obsidian` → `plugins`. Включите показ скрытых файлов, если папка не видна.
- **Android:** файловый менеджер → папка хранилища → `.obsidian/plugins`.
  На Android 11+ доступ к `Android/data` может быть ограничен — проще держать
  хранилище в `Documents`.

Альтернатива для обоих: положите папку `conference-tracker` в хранилище на компьютере,
а затем синхронизируйте хранилище (Obsidian Sync, iCloud, Dropbox, Syncthing, Git).
В Obsidian Sync включите **Settings → Sync → Vault configuration sync → Installed community plugins**
(«Синхронизировать установленные плагины»), иначе на телефоне плагин не появится.

### 3.6. Включение

1. Перезапустите Obsidian (или `Ctrl/Cmd + R` → «Reload app without saving»).
2. **Настройки → Сторонние плагины** (Community plugins).
3. Если видите предупреждение об ограниченном режиме — нажмите **Turn off restricted mode**
   / «Отключить ограниченный режим» и подтвердите.
4. В разделе **Установленные плагины** найдите **Conference Tracker** и включите
   переключатель.

Если плагин не появился в списке — см. [раздел 12](#12-частые-проблемы).

## 4. Первый запуск

После включения плагин добавляет три события: «Агронеделя», «Технопром», «День поля».
Дат и мест в них нет — только официальные сайты-источники.

При первом запуске плагин сразу загружает даты и места с этих сайтов
(настройка «Автообновление» включена). Это может занять несколько секунд.
Если сайт недоступен или дат на странице ещё нет, карточка останется с подписью
«Дата уточняется», а ошибку можно увидеть в настройках и повторить обновление вручную.
Дату и место всегда можно вписать вручную — плагин не перезапишет их без спроса.

Открыть панель можно тремя способами:

1. **Иконка календаря** на левой ленте (ribbon).
2. **Палитра команд**: `Ctrl/Cmd + P` → *Конференции: открыть панель конференций*.
3. Автоматически при запуске — включите настройку **«Открывать панель при запуске Obsidian»**.

Панель открывается справа. Её можно перетащить в другую область или закрепить.

## 5. Как устроена панель

Сверху вниз:

- **Заголовок** — количество событий и подсказка, через сколько дней ближайшее.
  Кнопки: `+` (добавить) и ↻ (обновить даты и места с сайтов).
- **Фильтры** — «Предстоящие» (по умолчанию), «Все», «Прошедшие». В скобках-счётчиках
  видно количество событий в каждой вкладке. Вкладка «Прошедшие» скрывается, если
  в настройках отключён показ прошедших.
- **Ближайшее событие** — крупная цифра «через N дней». Если событие идёт сегодня —
  «Идёт · день 2 из 3», если это последний день — «Финал».
- **Список** — сгруппирован по месяцам, события без даты — в блоке
  «Дата уточняется», завершившиеся — в блоке «Прошедшие».
- **Карточка** — название, полное название, бейдж статуса, даты и место ближайшего
  проведения, заметка, категория и ссылка «Сайт ↗». Пока данные не загрузились,
  вместо даты написано «Дата уточняется». Ниже — строка
  **«Прошлый раз: 16–18 июля 2026 · Алтайский край · Сибирский агропарк»**
  (пример уже загруженных данных). Показывается только одно актуальное прошлое
  проведение. Если дата и место пришли с сайта, рядом
  с датой стоит пометка «авто»; если сайт разошёлся с ручной датой — строка
  «На сайте: …». Кнопки редактирования, удаления и обновления появляются при
  наведении (на телефоне видны всегда).

У идущего события фон слегка зеленеет относительно фона темы, а цвет текста плагин
подбирает по фактическому контрасту — карточка остаётся читаемой и в светлой, и в тёмной
теме, даже если тема использует яркий «успешный» цвет.

Цвет левой полосы карточки зависит от категории: форум — синий, выставка — зелёный,
конференция — фиолетовый, день поля — оранжевый.

## 6. Работа с событиями

### 6.1. Добавить событие

1. Нажмите `+` в панели (или выполните команду **Добавить событие**).
2. Заполните поля:
   - **Название** — обязательное, именно оно показывается крупно.
   - **Полное название** — необязательное уточнение (например, «Сибирская аграрная неделя»).
   - **Категория** — форум, выставка, конференция, день поля или другое (влияет на цвет).
   - **Дата начала / окончания** — формат `ГГГГ-ММ-ДД`; в стандартном календаре
     Obsidian подставляет формат сам. Это ближайшее проведение.
   - **Место** — где проходит именно это проведение.
   - **Сайт** — официальная страница; из неё же по умолчанию берётся источник
     автообновления.
   - **Заметка** — свободный текст, например «регистрация до 1 июля».
   - **История проведений** — даты и место прошлых проведений. В карточку попадёт
     только актуальное (текущий или прошлый год); остальные строки остаются в форме
     и сохраняются, но в виджете не показываются. Можно оставить пустым.
3. Нажмите **Добавить**.

Если дата окончания окажется раньше даты начала или та же дата уже есть в истории,
плагин попросит исправить.

### 6.2. Событие без точной даты

Если организаторы ещё не объявили даты:

1. Включите тумблер **«Дата уточняется»** — поля точных дат скроются.
2. Укажите **ориентировочный месяц** (например, `2027-08`).

В виджете появится бейдж «Дата уточняется» и подпись «Ориентир: август 2027».
Когда точная дата будет объявлена, откройте событие, выключите тумблер и впишите даты.

### 6.3. Изменить или удалить

- Наведите курсор на карточку → значок карандаша (изменить) или корзины (удалить).
- Удаление подтверждается отдельным окном.
- Отменить удаление нельзя, но можно вернуть три события по умолчанию в настройках.

### 6.4. Прошлые проведения

Раздел **«История проведений»** в форме события — это список проведений по годам.
Для каждой строки задаются дата начала, дата окончания и место.

Что попадает в карточку и во вкладку «Прошедшие»:

- **событие уже прошло в текущем году** — показывается проведение этого года;
- **событие ещё ожидается в текущем году** — показывается проведение прошлого года;
- **прошло два года назад и раньше** — не показывается.

Пример, когда даты уже загружены с сайтов (на 8 ноября 2026 года):

| Событие | Что видно как «Прошлый раз» | Почему |
| --- | --- | --- |
| Агронеделя | 5–7 ноября 2025 | проведение 2026 года ещё впереди |
| Технопром | 26–28 августа 2026 | в 2026 году уже прошло |
| День поля | 16–18 июля 2026, Алтайский край | в 2026 году уже прошло |

Поэтому вкладка «Прошедшие» — это не многолетний архив, а только то, что помогает
сориентироваться перед следующим проведением.

- Порядок в форме не важен: плагин сам сортирует проведения и убирает дубли.
- Когда событие проходит, его дата остаётся в списке; добавьте следующее проведение,
  когда организаторы его объявят.
- Проведения вне разрешённых регионов не показываются в форме и удаляются при
  сохранении; добавить новое «чужое» место нельзя — форма попросит исправить.

> «День поля» — это **Всероссийский день поля**, но плагин учитывает его
> только в **Новосибирской области и Алтайском крае**. Если на сайте найдётся дата
> в другом регионе (например, в Ставропольском крае или Волгоградской области),
> она не будет добавлена и не появится в карточке. Региональный «День поля
> Новосибирской области» — другое мероприятие; при необходимости добавьте его
> отдельным событием.

Пример допустимой записи (регионы — НСО и Алтай):

| Начало | Окончание | Место |
| --- | --- | --- |
| 2026-07-16 | 2026-07-18 | Алтайский край · Сибирский агропарк, пос. Прутской |

### 6.5. Автообновление с сайтов

В форме события есть блок **«Автообновление»**:

- тумблер **«Искать даты на официальном сайте»**;
- поле **«Источники»** — по одному адресу в строке; если пусто, используется адрес
  из поля «Сайт».

Что делает плагин при обновлении:

1. Загружает страницу (до 15 секунд на источник).
2. Сначала ищет разметку `schema.org/Event` (JSON-LD) — из неё берёт даты и адрес.
3. Если разметки нет, ищет в тексте диапазоны вида «16–18 июля 2026»,
   «с 3 по 5 июля 2025», «10–12 ноября» и место рядом с датой.
4. Добавляет найденное **будущее** проведение или уточняет место у уже известной даты.
5. У «Дня поля» проверяет регион: даты вне Новосибирской области и Алтайского края
   игнорируются с сообщением «Дата вне разрешённых регионов».

Правила безопасности:

- ручное будущее проведение **не перезаписывается**; при расхождении в карточке
  появляется строка «На сайте: …», а дата остаётся вашей;
- автоматически найденная дата помечается чипом «авто» — её легко отличить от ручной;
- если сайт не ответил или дат не нашлось, плагин пишет об этом в настройках
  и в карточке, но данные не портит.

Плагин запускает проверку при старте и при открытии панели, но не чаще выбранного
интервала. Обновить вручную можно кнопкой ↻ в заголовке, командой
**«Обновить даты и места с сайтов»** или кнопкой у конкретного события.

### 6.6. Ссылки

Кнопка **«Сайт ↗»** открывает адрес в браузере. Можно вводить адрес без `https://` —
плагин добавит схему сам.

## 7. Виджет внутри заметки

Вставьте в любую заметку блок кода с языком `conferences`:

````markdown
```conferences
view: upcoming
hero: true
```
````

В режиме чтения (и в реальном времени) на месте блока появится виджет. Он использует те
же события, что и боковая панель: изменили дату в панели — обновился и блок в заметке.

### 7.1. Параметры блока

| Параметр | Значения | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `view` (или `mode`) | `upcoming`, `all`, `past` | `upcoming` | Начальная вкладка |
| `limit` | число | `0` — без ограничения | Сколько событий показать |
| `hero` | `true` / `false` | `true` | Показывать блок «Ближайшее событие» |
| `filters` | `true` / `false` | `true` | Показывать вкладки-фильтры |
| `compact` | `true` / `false` | `true` в заметке | Компактные карточки |
| `title` | текст | — | Заголовок над виджетом |

Неизвестные параметры игнорируются, регистр не важен.

### 7.2. Примеры

Только ближайшие пять событий, без блока «Ближайшее»:

````markdown
```conferences
view: upcoming
limit: 5
hero: false
```
````

Полный список с архивом и своим заголовком:

````markdown
```conferences
view: all
title: Мероприятия 2026–2027
compact: false
```
````

Только прошедшие — для раздела «Архив»:

````markdown
```conferences
view: past
filters: false
```
````

Если после правки блока виджет не обновился, закройте и снова откройте заметку — так
Obsidian перерисовывает блоки кода.

## 8. Настройки

**Настройки → Сторонние плагины → Conference Tracker** (шестерёнка) или
**Настройки → Conference Tracker** в левом списке.

| Настройка | По умолчанию | Описание |
| --- | --- | --- |
| Показывать прошедшие события | включено | Вкладка «Прошедшие» и архив в «Все» |
| Показывать события с неуточнённой датой | включено | События с ориентиром вместо даты |
| Показывать блок «Ближайшее событие» | включено | Крупный счётчик над списком |
| Открывать панель при запуске Obsidian | выключено | Автоматически открывать панель |
| Обновлять даты и места с официальных сайтов | включено | Читать страницы источников и добавлять проведения |
| Как часто проверять | раз в 12 часов | При запуске Obsidian, не чаще выбранного интервала (1/6/12/24/72 часа) |

Под блоком автообновления видно, когда была последняя проверка и что она нашла.
Кнопка **«Обновить»** запускает проверку сразу.

Внизу — кнопки **«Скопировать список как Markdown»** (таблица с местами и прошлым
проведением) и **«Сбросить события к исходным»** (возвращает три события по умолчанию
и заново загружает даты с сайтов, если автообновление включено).

Если автообновление не нужно, выключите его — плагин перестанет обращаться к сайтам
и будет работать полностью офлайн.

## 10. Где хранятся данные

Все события и настройки лежат в одном файле:

```
<хранилище>/.obsidian/plugins/conference-tracker/data.json
```

- **Резервная копия** — просто скопируйте `data.json`.
- **Перенос в другое хранилище** — скопируйте всю папку `conference-tracker` вместе
  с `data.json`.
- **Синхронизация** — файл синхронизируется вместе с настройками плагинов, если в
  Obsidian Sync включён пункт «Installed community plugins». При синхронизации через
  Git добавьте `.obsidian/plugins/conference-tracker` в репозиторий хранилища.
- **Только события, без настроек** — при необходимости можно отредактировать JSON
  вручную: структура описана в [разделе 14](#14-устройство-плагина). Перед правкой
  сделайте копию файла.

Формат дат в данных — `ГГГГ-ММ-ДД` (`2026-11-10`), ориентировочный месяц — `ГГГГ-ММ`.
Каждое событие содержит массив `editions` — проведения по годам. Подробная структура —
в [разделе 14](#14-устройство-плагина).

При обновлении с версии 1.0.0 ничего переносить не нужно: старые поля `start`, `end`,
`place` и `previous` читаются автоматически и превращаются в первое проведение
и заметку об истории. Резервную копию `data.json` всё равно стоит сделать перед
обновлением.

## 11. Как поддерживать даты актуальными

Даты и места не нужно вносить в код или вручную заполнять в `data.json`: плагин
делает это сам.

**Автозагрузка.** При старте Obsidian и при открытии панели плагин читает страницы
источников, но не чаще выбранного интервала (по умолчанию — раз в 12 часов).
Если находит будущую дату, добавляет проведение; если дата уже есть, уточняет место.
Прошедшее проведение текущего или прошлого года тоже сохраняется — оно нужно для
строки «Прошлый раз». Найденное помечается чипом «авто».

**Ручная проверка — только если сайт ничего не отдал.** События с бейджем
«Дата уточняется» стоит проверить:

1. Нажмите «Сайт ↗» и сверьте даты и площадку.
2. Появилась точная дата — откройте событие, выключите «Дата уточняется» и впишите
   даты и место. Если дата уже добавлена автоматически, просто проверьте её.
3. После проведения события ничего удалять не нужно: дата остаётся в истории,
   а для следующего года добавляется новое проведение (вручную или с сайта).
4. Если сайт пишет одно, а вы знаете другое (перенос, смена площадки), оставьте
   ручную дату — плагин покажет расхождение строкой «На сайте: …», но не затрёт её.

Пример для «Дня поля»: когда сайт сообщит дату в Алтайском крае, она появится
в карточке и станет «Прошлым разом» после проведения. Дату в другом регионе плагин
не добавит — он учитывает только Новосибирскую область и Алтай и сообщит
«Дата вне разрешённых регионов».

## 12. Частые проблемы

**Плагина нет в списке установленных**

- Проверьте путь: должно быть `.obsidian/plugins/conference-tracker/manifest.json`.
  Частая ошибка — вложенная папка `conference-tracker/conference-tracker`.
- Убедитесь, что `.obsidian` — папка именно вашего хранилища, а не другого.
- Перезапустите Obsidian полностью, а не просто закройте окно.

**Плагин есть, но при включении ошибка «Failed to load plugin»**

- Проверьте, что в папке лежит `main.js` (не `main.ts`, не `main.js.txt`).
- Обновите Obsidian до 1.4.0 или новее.
- Откройте консоль разработчика (`Ctrl/Cmd + Shift + I`) и посмотрите текст ошибки.

**Не открывается панель**

- Попробуйте команду из палитры команд — возможно, панель просто скрыта в другой
  области экрана.
- На очень узком окне правая панель может быть свёрнута — разверните её.

**В заметке вместо виджета — пусто или код**

- Плагин выключен. Включите его в настройках и переоткройте заметку.
- Блок должен начинаться ровно с ```` ```conferences ```` (три обратные кавычки и слово
  `conferences`).

**Счётчик показывает «не то» число дней**

- Счётчик считает календарные дни по локальной дате устройства и не учитывает время
  начала. «Завтра» означает, что событие начнётся на следующий календарный день.

**Автообновление не находит даты**

- Сайт может отдавать расписание картинкой или подгружать его скриптом — текстовый
  разбор такое не видит. Внесите дату вручную.
- Проверьте адрес в блоке «Источники»: нужна конкретная страница события, а не главная
  сайта. Если поле пустое, используется адрес из «Сайт».
- Посмотрите сообщение в настройках: там указано, какой источник и с какой ошибкой
  не сработал.

**В карточке написано «На сайте: …», но дата другая**

- Это не ошибка, а защита от перезаписи: у события уже есть ручное будущее проведение,
  и плагин не стал его менять. Сверьтесь с сайтом и при необходимости поправьте дату
  вручную — пометка исчезнет после следующей проверки.

**Сайт отвечает 403 или таймаутом**

- Часть сайтов блокирует автоматические запросы. Плагин покажет ошибку и продолжит
  работать с уже сохранёнными данными; дату можно внести вручную.
- Проверьте интернет и повторите обновление позже.

**Не сохраняются изменения**

- Хранилище доступно только для чтения (сетевой диск, папка без прав записи).
- Конфликт синхронизации: закройте Obsidian на других устройствах и повторите.

**Сбросились события**

- Восстановите `data.json` из резервной копии или нажмите «Сбросить события к исходным»
  в настройках.

## 14. Устройство плагина

```
conference-tracker/
  manifest.json   манифест: id, имя, версия, минимальная версия Obsidian
  main.js         логика дат и проведений, разбор сайтов, панель, блок кода, формы, настройки
  styles.css      стили на переменных темы Obsidian
```

Сборки нет: `main.js` — обычный CommonJS-файл, который Obsidian загружает напрямую.
Даты, проведения и статусы считаются в чистых функциях (`editionState`,
`getNearestEdition`, `getLastPastEdition`, `buildItems`), разбор страниц вынесен
в `parseEventPage`, а слияние с данными — в `applySyncCandidate`. Поэтому всё это
покрывается тестами без Obsidian.

Запуск тестов (нужен Node.js 20+):

```bash
npm install
npm test
```

64 теста проверяют разбор дат и мест, склонения, статусы, сортировку, фильтры,
актуальное прошлое, ограничение по регионам, JSON-LD и текстовый разбор страниц,
защиту от перезаписи ручных дат, отрисовку панели и заметки, формы события и команды.

Структура `data.json` (версия 2; пример — событие после автообновления):

```json
{
  "version": 2,
  "events": [
    {
      "id": "field-day",
      "title": "День поля",
      "fullTitle": "Всероссийский день поля",
      "category": "День поля",
      "url": "https://russian-field-day.ru/",
      "note": "Главная полевая выставка страны; регион меняется каждый год.",
      "expectedMonth": "2027-07",
      "regions": ["Новосибирская область", "Новосибирск", "Алтай"],
      "editions": [
        {
          "id": "field-day-2026",
          "start": "2026-07-16",
          "end": "2026-07-18",
          "place": "Алтайский край · Сибирский агропарк, пос. Прутской",
          "url": "https://russian-field-day.ru/",
          "note": "",
          "source": "auto",
          "sourceUrl": "https://russian-field-day.ru/",
          "checkedAt": ""
        }
      ],
      "historyNote": "",
      "sync": {
        "enabled": true,
        "sources": ["https://russian-field-day.ru/"],
        "lastSync": "2026-11-08T10:00:00.000Z",
        "lastResult": "",
        "lastError": ""
      },
      "createdAt": "2026-11-08T10:00:00.000Z"
    }
  ],
  "settings": {
    "showPast": true,
    "showTentative": true,
    "showHero": true,
    "openOnStartup": false,
    "autoSync": true,
    "syncIntervalHours": 12,
    "lastSyncAt": "",
    "lastSyncSummary": ""
  }
}
```

- `editions` — проведения по годам; порядок не важен, плагин сортирует сам.
  В интерфейсе показывается только актуальное прошлое (текущий или прошлый год).
- `start` обязателен; `end` можно не указывать — проведение будет однодневным.
- `source` — `manual` (внесено вручную) или `auto` (найдено на сайте).
- `expectedMonth` — ориентир `ГГГГ-ММ`, если будущая дата ещё не объявлена.
- `regions` — необязательный список разрешённых регионов. Если он задан, проведения
  с местом вне списка не показываются, а автообновление их не добавляет.
- `historyNote` — необязательная свободная заметка о прошлых проведениях; она
  показывается, только если нет структурированного прошлого проведения.
- Данные версии 1 (поля `start`, `end`, `place`, `previous`) читаются автоматически:
  дата становится первым проведением, `previous` — заметкой об истории.
- Неизвестные поля игнорируются, поэтому файл можно править вручную без риска
  сломать плагин (но лучше сделать копию).
